# 문제풀이도구 (QuizBench)

화면에 띄운 문제를 여러 AI 에게 한꺼번에 풀리고, 정답지와 대조해 **AI 별 정답률**을 재는
설치형 도구. `C:\vibe` 의 다른 도구들과 같은 틀(로컬 Node 서버 + SEA 단일 exe + Inno Setup)이다.

한글·엑셀·크롬·엣지 — `PrintWindow` 로 그릴 수 있는 창이면 무엇이든 대상이 된다.

## 내려받기

**[Releases 에서 `문제풀이도구.exe` 를 받으세요](../../releases/latest)** — 그 파일 하나면 됩니다.
Node.js 도, 따로 설치할 것도 없습니다. 두 번 누르면 브라우저가 열리고, 검은 창을 닫으면 끝납니다.

윈도우 전용입니다(창 캡처에 `PrintWindow` 를 씁니다).
처음 실행할 때 창 캡처 도우미를 한 번 컴파일합니다 — 몇 초 걸립니다.

> **API 키는 각자 준비해야 합니다.** 이 도구는 키를 들고 있지 않습니다.
> 넣은 키는 이 PC 의 `%APPDATA%\QuizBench\settings.json` 에만 저장되고,
> 그 AI 회사 말고 **어디로도 가지 않습니다**. 어느 키를 어디서 받는지는 `사용법.txt` 에 있습니다.

## 무엇을 하는가

1. 지금 열린 창 목록을 보여 주고, 고른 창을 PNG 로 찍는다.
   긴 문제지는 **맨 위로 되감고 굴려 내리며 여러 장**을 찍는다 (일부만 잘라내기도 가능).
2. **찍은 장 전부**를 켜 둔 AI 모두에게 **똑같은 지시문**과 함께 동시에 보낸다.
3. 돌아온 답에서 `{번호: 답}` 과 `{번호: 근거}` 를 캐낸다.
4. 사람이 넣은 정답지와 대조해 AI 별 정답률·문항별 표를 만든다.
5. 표에서 답을 누르면 그 문항에 대한 **AI 들의 근거를 나란히** 보여 준다.
6. CSV 로 내보낸다(근거 칸 포함).

AI 줄은 화면에서 늘리고 줄일 수 있다(12줄까지). 갈래를 골라 넣으므로
**같은 회사의 다른 모델끼리도 견줄 수 있다** — opus 대 haiku 처럼.

## AI 어댑터

| 종류 | 통로 | 비고 |
| --- | --- | --- |
| `anthropic` | `@anthropic-ai/sdk` → `messages.create` | 이미지 base64 블록. 생각하기·effort 조절 |
| `openai` | `openai` → `responses.create` | `input_image` 에 data URI |
| `google` | `@google/genai` → `models.generateContent` | `inlineData` |
| `upstage` | 생 `fetch` → **두 걸음** (아래 참고) | Solar 는 그림을 못 읽는다 |
| `compatible` | 생 `fetch` → `/v1/chat/completions` | 국내 모델·사내 서버용 |

네 갈래 모두 `ask(provider, {pngs, prompt, timeoutMs, signal})` → `{text, usage, ms}` 로 같은 모습이다.
`pngs` 는 늘 배열이다(`asPngs()` 가 한 장도 배열로 만든다) — 갈래마다 "한 장일 때" 를
따로 두면 거기서 어긋난다. 여러 장이면 그림 앞에 `N번째 장 (전체 M장)` 쪽지를 끼우고,
한 장이면 안 끼운다(쓸데없는 토큰).
`baseUrl` 을 주면 어느 갈래든 다른 주소로 돌릴 수 있다(자체 점검이 이걸 쓴다).

### 견주기의 전제 — 일부러 지킨 것

- **지시문이 모두에게 글자 하나까지 똑같이 간다.** 어느 한쪽에만 구조화 출력이나
  예시를 더 얹으면 그건 모델의 실력이 아니라 우리가 만든 차이가 된다.
  그래서 답 형식은 "JSON 으로 달라" 고 **말로만** 부탁하고, 안 지킨 답은
  `grade.parseLoose()` 가 줄글에서 주워 담는다(그리고 화면에 "형식 안 지킴" 이라고 적는다).
- **사진은 한 번만 찍어 모두에게 같은 것을 보낸다.** AI 마다 따로 찍으면
  그사이 화면이 바뀌어 견주기가 무너진다.
- **Anthropic 의 서버 쪽 대체 모델(`fallbacks`)을 켜지 않는다.** 대체가 돌면
  `claude-opus-5` 를 재려던 자리에 다른 모델의 답이 조용히 들어와 측정이 어긋난다.
  거절은 대체하지 않고 "거절됨" 으로 보여 준다. (자체 점검이 이걸 확인한다.)
- 생각하기를 끄면 `effort` 를 `high` 위로 올리지 않는다 — 그 조합은 400 이다.

## API 키를 다루는 규칙

키가 이 도구에서 가장 위험한 것이라, 길목을 하나로 좁혀 두었다.

- 원문은 `%APPDATA%\QuizBench\settings.json` 에만 있고, 그 회사 말고 어디로도 안 간다.
- **브라우저로 나가는 모든 응답은 `store.safeSettings()` 를 거친다** — `apiKey` 를 빼고
  `hasKey`(있다/없다)와 `keyHint`(가린 값)만 싣는다.
- 화면에서 키 칸을 비워 보내면 "그대로 두기" 로 본다. 그래서 가린 값을 되돌려 보내도 안전하다.
- `store.redact()` 가 마지막 그물이다. SDK 오류 문구·URL 에 키가 섞여 나오는 일이 있어서,
  화면·기록으로 나가는 글을 한 번 씻는다. 저장 안 된 키도 생김새(`sk-…`, `AIza…`)로 가린다.
- 자체 점검이 **자식 서버를 진짜로 띄워** `/api/env`·`/api/state`·`/api/runs`·설정 저장 응답의
  **원문 전체**를 훑어 키가 섞였는지 본다.

## 채점

`lib/grade.js` 는 바깥과 이야기하지 않는 함수만 있어서 점검이 마음껏 두드릴 수 있다.

- `normalize()` — `③`·`４`·`정답: 3번`·`007`·`3.0` 을 모두 `3` 으로. 단 `1` 과 `10` 은 안 뭉갠다.
- `parseAnswers()` — 곧은 JSON → ```` ```json ```` 울타리 → 글 속 첫 `{…}` → 줄글 줍기 차례로 시도.
- `parseKey()` — 정답지 모양을 가르는 규칙을 못 박아 두었다.
  여러 줄이면 줄마다 "번호 답", 한 줄에 짝이 둘 이상이면 `1.3 2.4`,
  한 줄인데 기호가 또렷하면 그 하나, 그 밖의 한 줄은 **번호 없는 답 목록**.
  (`3 4 1` 은 답 목록이다. 번호를 매기려면 줄을 나누거나 점을 찍어야 한다.)
- `grade()` — 맞음/틀림/못 씀을 나눠 센다. "못 씀" 을 "틀림" 과 구별하는 것이 중요하다.
  화면을 못 읽은 것과 답을 틀린 것은 다른 일이다.
- 모든 AI 가 틀린 문항을 따로 집어낸다 — 대개 문제가 어렵거나 그 부분이 안 읽힌 자리다.

여러 번 물었을 때(`repeat`)는 가장 잦은 답을 골라 쓰고, **흔들린 자리에만** `2/3번만` 을 붙인다.
늘 같은 답이면 아무것도 안 적는다 — 그래야 정작 봐야 할 자리가 안 묻힌다.

## 모델 이름이 틀렸을 때

모델 이름은 회사가 자꾸 바꾸고 옛 것은 문을 닫는다. 실제로 사용자가 두 번 막혔다 —
`gemini-3-pro`(우리가 잘못 넣은 기본값)와 `groq`(Grok 과 Groq 을 헷갈림). 그래서 두 겹으로 막는다.

- **404 나 "does not exist" 를 받으면 그 자리에서 `listModels()` 를 불러 쓸 수 있는 이름을 붙인다.**
  `"groq" 라는 모델이 없습니다. 쓸 수 있는 이름: grok-4.6, grok-4.3 …` 처럼 나온다.
  임베딩·TTS 처럼 문제 풀이에 못 쓰는 것은 빼고 보여 준다. 이름 물어보기가 실패해도 조용히 넘어간다.
- **우리가 잘못 내보낸 기본값은 `RETIRED_MODELS` 로 갈아 끼운다.** 저장된 값이 우리가 내보냈던
  그 값 그대로일 때만 바꾼다 — 사용자가 손으로 고른 이름은 건드리지 않는다.
  점검이 "지금 기본값이 못 쓰는 목록에 들어 있지 않은지" 도 함께 본다(스스로 모순 방지).

### Grok(xAI) 은 호환 갈래 + 주소를 미리 채운 줄

`https://api.x.ai/v1` 로 OpenAI 모양 그대로 간다. 새 갈래를 만들 것 없이 `compatible` 에
주소를 미리 넣어 둔 기본 줄을 하나 뒀다 — 주소를 외우게 하면 안 되고,
**Groq(다른 회사)과 헷갈리는 것도 이름표로 막는다.**

## Upstage Solar — 그림을 못 읽는 모델을 끼우는 법

**Solar 의 `/v1/chat/completions` 는 이미지 입력을 받지 않는다.** 공식 API 레퍼런스가
"does not support image input via `image_url`" 라고 못 박고 있다. 그래서 다른 갈래처럼
화면 사진을 던지면 **한 문제도 못 푼다** — 사용자가 겪은 일이 정확히 이것이었다.

대신 Upstage 에는 그림에서 글자를 뽑는 통로가 **같은 키로** 열려 있다. 그래서 두 걸음:

```
PNG → POST /v1/document-digitization (model: document-parse | ocr) → 글자
글자 + 지시문 → POST /v1/chat/completions (solar-pro4 …) → 답
```

- 실측(2026-08-28): `api.upstage.ai/v1` 의 `/chat/completions`·`/models`·`/document-digitization`
  모두 살아 있다(키 없이 401 — 404 가 아니다). 주소 문제가 아니었다는 뜻이다.
- 뽑기 응답의 글자 자리가 통로마다 다르다(`ocr` 은 `text`, `document-parse` 는 `content.*`).
  `pickOcrText()` 가 있을 만한 자리를 차례로 본다 — 못 찾으면 빈 글자를 주고 부르는 쪽이 알린다.
- 여러 장이면 장마다 뽑아서 `[N번째 장]` 을 붙여 이어 붙인다.

### 이것만은 숨기면 안 된다

이 갈래만 **입력이 다르다.** 다른 AI 는 그림을 보고 이쪽은 글자만 본다.
그래프 모양·도형처럼 그림으로만 알 수 있는 문제는 Solar 에게 불리하다.
견주는 도구에서 이 차이를 숨기면 정답률이 거짓말이 되므로, `viaText` 를 결과에 실어
**요약 딱지에 "글자로 읽음", 표 머리글에 "(글자)"** 를 늘 붙인다.
점검이 "Solar 요청에 그림이 실리지 않았는지" 와 "뽑은 글이 풀이 요청에 실렸는지" 를 확인한다.

## 파일 올려서 풀기

창을 찍는 대신 파일을 그대로 준다. 세 갈래로 갈린다.

| 올린 것 | 어떻게 | 어디서 |
| --- | --- | --- |
| 사진(jpg·png·webp…) | 그대로 PNG 로 | 브라우저 |
| **PDF** | 쪽마다 그림으로 구움 (pdf.js, 30쪽까지) | 브라우저 |
| 한글·워드·엑셀·PPT·텍스트 | 글자를 뽑아 **글로** 푼다 | 서버(`lib/peek.js`) |

- pdf.js 알맹이(`vendor\`, 4.3MB·200파일)는 `PDF이미지변환기` 에서 그대로 가져왔고
  exe 안에 함께 들어간다. 목록은 손으로 안 적고 `runtime.vendorFiles()` 가 폴더를 훑는다.
- **`.mjs` 의 MIME 을 빠뜨리면 pdf.js 가 아예 안 뜬다.** 브라우저는 모듈 스크립트의
  MIME 을 엄격히 본다(`application/octet-stream` 이면 거부). `.wasm`·`.ttf` 도 함께 넣어 뒀다.
- **브라우저는 보이지 않는 창을 그리지 않는다.** PDF 를 올려 놓고 다른 창으로 가면
  `page.render()` 가 끝나지 않는다(OffscreenCanvas 로 해도 마찬가지다 — `document.hidden` 이면 멈춘다).
  뚫을 수 없는 규칙이라 `waitVisible()` 로 **왜 멈췄는지 알려 주고** 돌아오면 잇는다.
- `peek.js` 는 문서정리기에서 가져오되 **한도를 올렸다.** 거기서는 분류용 6000자면 됐지만
  여기서는 문제지 전체가 있어야 뒷 문제를 푼다(200000자, zip 항목 60개).
  점검이 900문항짜리로 안 잘리는지 확인한다.
- 글자로 온 문제지는 `providers.askWithText()` 로 간다 — 어느 갈래든 그림 없이 물어볼 수 있고,
  Upstage 와 같은 `viaText` 표시가 붙는다.

## 지난 기록 지우기

`store.deleteRun()` 이 기록과 **그때 찍은 그림을 함께** 없앤다(기록만 지우면 폴더가 조용히 불어난다).
`shotKeys` 에 적힌 이름을 그대로 믿지 않고 `^[A-Za-z0-9_-]{1,40}$` 로 거른다 —
기록 파일이 바깥 파일을 가리키면 그것만 건너뛴다. 점검이 이걸 실제로 확인한다.
`clearRuns()` 는 `preview*` 를 남긴다 — 지난 기록을 지웠다고 눈앞의 미리보기까지 사라지면 놀란다.

## 창 잡기 · 굴려 내리기

- **최소화된 창을 크기로 거르면 안 된다.** 윈도우는 최소화된 창의 크기를 `314×50` 같은
  껍데기 값으로 준다. 크기 잣대를 그대로 대면 작업 표시줄에 내려간 창이 통째로 사라진다 —
  **한글 문서 창이 목록에 안 보이던 까닭이 이것이었다.** 점검이 "최소화된 창이 목록에
  남아 있는지" 를 실제로 확인한다.
- 최소화된 창은 찍기 전에 `activate{restore:true, front:false}` 로 **포커스를 빼앗지 않고**
  되살린다(`SW_SHOWNOACTIVATE` → `HWND_BOTTOM`). 사용자가 하던 일이 끊기지 않는다.
- **굴리기 쪽지는 자식 창에게 보내야 한다.** 크롬·엣지의 문서 바닥은
  `Chrome_RenderWidgetHostHWND` 라, 맨 위 창에 `WM_MOUSEWHEEL` 을 보내면 아무도 안 받는다.
  `Win.Wheel` 에 `Click` 과 같은 자식 찾기(두 단계)를 넣어 고쳤다.
  좌표는 누르기와 달리 **화면 기준**이다.
- **먼저 맨 위로 되감는다.** 사용자가 문서를 중간까지 내려 둔 채 찍으면 앞 문제가 빠진다.
  "몇 번 굴리면 맨 위" 를 알 수 없으니 **그림이 더 안 바뀔 때까지** 올린다(최대 6번).
- 끝은 **지문(해시)이 다시 나오는 것**으로 안다. 장끼리 겹쳐도 괜찮다 —
  같은 문제는 번호로 한 번만 세기 때문이다.
- 둘째 장이 첫 장과 같을 때 "굴리기가 안 먹는다" 고 **단정하지 않는다.**
  문서가 짧은 경우가 훨씬 흔하다. 두 가능성을 다 말해 준다.
- 영역을 고르면 굴리지 않는다 — 고른 자리에 다른 내용이 흘러들어 "보이는 그대로" 가 깨진다.
- **폭이 넘치면 오른쪽 문제가 통째로 빠진다**(2단 시험지에서 흔하다). `wide` 로 고른다:
  `fit` 은 Ctrl+휠로 **들어올 때까지만** 배율을 줄이고(최대 6칸, 안 먹으면 즉시 포기),
  `side` 는 배율을 두고 옆으로도 훑어 찍는다(문제가 쪼개질 수 있다), `off` 는 그냥 둔다.
  `overflowsRight()` 가 옆으로 굴려 보고 그림이 바뀌는지로 넘침을 판정하고 **반드시 제자리로 돌려놓는다.**
  Ctrl+휠은 `worker.cs` 의 `Wheel(..., ctrl)` 이 `MK_CONTROL` 을 실어 보낸다.
- **점검은 진짜 창을 굴리지 않는다.** 굴리기는 사용자가 보던 창을 실제로 움직이므로,
  점검하자고 남의 창을 되감아 놓으면 안 된다(화면 모드와 문구로만 확인한다).

실측(2026-08-28): 크롬 6장 3.8초, 한글 3장 4.8초(되감기 포함). 장마다 지문이 모두 달랐다.

## 근거(왜 그 답인지)

지시문을 두 벌 준비해 두고 화면의 "해설도 받기" 가 갈아 끼운다(`store.PROMPT_WHY` / `PROMPT_PLAIN`).
켜면 `{"no":"1","answer":"3","why":"…"}` 를 받는다. 두 벌 다 **모든 AI 에게 똑같이** 가므로
공평함은 그대로다. 사용자가 손으로 고쳐 쓴 지시문은 확인 없이 덮어쓰지 않는다.

- `grade.pickWhy()` 가 `why`·`reason`·`이유`·`풀이` 등 여러 이름을 받아 준다 — 모델마다 다르게 부른다.
- **해설은 이긴 답을 낸 시도의 것이어야 한다.** 여러 번 물었을 때 아무 해설이나 집어 오면
  "답은 3인데 해설은 4를 고른 까닭" 이 된다. `run.consensus()` 가 답과 해설을 함께 센다.
- **답이 비어도 해설은 살린다.** "보기가 잘려 못 읽었습니다" 가 바로 그 자리인데,
  답이 없다고 해설까지 버리면 정작 궁금한 것이 안 남는다.
  (이 도구에서 실제로 났던 버그다. 점검이 두 경우를 다 붙잡는다.)
- 줄글에서 주운 답에는 해설이 없다 — 없다고 정직하게 말하고 원문을 보여 준다.

화면에서는 답을 누르면 **그 문항의 모든 AI** 가 답·맞음여부·근거·원문과 함께 뜨고,
누른 AI 가 맨 위로 온다. 정답률만으로는 "왜 틀렸는지" 를 알 수 없기 때문에 이 자리가 이 도구의 값이다.

## 빌드

```
npm install
node build.js              # dist\문제풀이도구.exe
.\build_installer.ps1      # dist\QuizBench_설치_1.0.0.exe
```

`build.js` 는 esbuild → `--experimental-sea-config` → rcedit → postject 순서로 돈다.
**rcedit 는 postject 주입 전**에 해야 한다. 끝에 `--selftest` 를 exe 안에서 돌려 보고,
통과하지 못하면 exe 를 지운다(`build_installer.ps1` 이 "있으면 건너뛰기" 라서 남기면 깨진 게 담긴다).

SDK 세 개(`@anthropic-ai/sdk`·`openai`·`@google/genai`)는 esbuild 가 한 덩어리로 묶는다(약 2.3MB).

## 자체 점검

```
node server.js --selftest
```

여섯 갈래를 본다. **점검은 `%APPDATA%` 를 임시 폴더로 돌려놓고 돌아서 사용자 자료를 건드리지 않는다**
(자식 프로세스에도 물려준다). `store.js` 는 불러오는 순간 저장 자리를 정하므로,
`server.js` 는 `--selftest` 를 **다른 무엇을 불러오기 전에** 갈라 낸다.

| 갈래 | 무엇을 |
| --- | --- |
| 채점 | 다듬기·읽어내기·정답지·채점 셈·CSV·**해설 캐내기와 이어 붙이기** |
| 키 가리기 | 화면으로 나가는 설정에 원문이 없는지, `redact` 가 씻는지 |
| AI 줄 관리 | 이름표 겹침·빠진 칸 메우기·**지운 줄이 되살아나지 않는지**·지시문 갈아 끼우기 |
| AI 통로 4갈래 | 가짜 서버를 띄워 네 어댑터가 실제로 그림·지시문을 보내는지 |
| 오류 옮기기 | 거절(HTTP 200 인데 `stop_reason: refusal`)·401 을 사람 말로 |
| 창 찍기 | `worker.cs` 를 **진짜로 컴파일**해서 화면을 찍어 PNG 인지 확인 |
| 서버 왕복 | 자식 서버를 띄워 키가 안 새는지·줄 더하기/지우기·해설 켜고 끄기 |
